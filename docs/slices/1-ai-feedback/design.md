## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **[G1] 입력 검증**: 빈 문장이나 공백만 있는 입력, 또는 1,000자를 넘는 입력은 AI를 부르기 전에 거절하고 화면에 안내 문구를 보여준다.
- **[G2] 첨삭 결과 3단 구성 보장**: AI 응답은 항상 ① 교정 문장 및 이유(`corrected`, `explanation`), ② 자연스러운 추천 표현 2~3개(`alternatives`: 표현 + 뉘앙스 설명), ③ 핵심 단어·표현 요약(`keyExpressions`: 표현 + 뜻 + 예문)의 고정된 모양(JSON 스키마)으로 받아 화면에 표시한다.
- **[G3] 자동 기록 보관**: 정상적으로 받은 모든 첨삭 결과는 생성 시각과 함께 로컬 파일(`data/feedback-history.json`)에 즉시 추가되며, 최신순으로 다시 조회할 수 있다.
- **[G4] API 키 보호**: `GEMINI_API_KEY`는 서버 환경변수에서만 읽으며, 브라우저 화면(클라이언트)이나 `git` 저장소에 노출되지 않는다.

**보장하지 않는 것(알려진 한계)**

- 인터넷 연결이 끊기거나 Google Gemini 서비스 장애가 발생했을 때는 새 첨삭을 받을 수 없다(단, 이미 저장된 이전 첨삭 기록은 볼 수 있음).
- 브라우저 음성 인식(Web Speech API)은 Chrome·Edge 등 지원하는 데스크톱 브라우저에서 동작하며, 주변 소음이 크면 글자 변환이 부정확할 수 있다(변환된 글자를 전송 전에 키보드로 직접 수정 가능).

## ③ 받는 입력

- **첨삭 요청 입력 (`POST /api/feedback`)**:
  - `text` (문자열, 필수): 공백을 제외한 길이 1자 이상 ~ 1,000자 이하의 영어 또는 한영 혼용 문장.
  - `inputMode` (`"text"` | `"voice"`, 선택, 기본값 `"text"`): 키보드로 입력했는지 마이크로 말해서 입력했는지 구분하여 기록에 남긴다.
  - 위 조건을 벗어난 입력(빈 문자열, 1,000자 초과, 다른 타입)은 `400 Bad Request`와 한국어 안내 메시지로 거절한다.

## ④ 결정

**정한 것 (업무에 영향이 없는 기술 결정 — 추천안으로 확정)**

- **실행 방식**: 별도의 복잡한 데이터베이스 설치 없이 내 PC에서 바로 켜고 쓸 수 있도록 가벼운 **Node.js(TypeScript + Express) 로컬 웹 서버 + 단일 웹 화면(HTML/CSS/JS)** 구조를 사용한다.
- **기록 저장소**: 추후 2번 조각(`vocab-review`)과 3번 조각(`study-routine`)에서도 쉽게 읽고 백업할 수 있도록 내 PC 폴더 안의 JSON 파일(`data/feedback-history.json`)에 저장한다(개인 공부 기록이 코드 커밋에 섞이지 않도록 `data/` 폴더는 `.gitignore`에 등록).
- **AI 출력 고정 방식**: Gemini API의 `responseSchema`(구조화된 JSON 출력 기능)를 사용해 AI가 항상 정해진 3단 구성(교정·추천 표현·핵심 단어)을 빠짐없이 채워 주도록 강제한다.
- **말하기(마이크) 입력**: 별도 유료 음성 API 없이 브라우저 내장 음성 인식(`webkitSpeechRecognition` / `SpeechRecognition`)을 사용해 마이크 버튼을 누르고 영어로 말하면 입력창에 실시간으로 글자가 채워지게 한다.

**열어 둔 것**

- 없음 — 1번 조각 구현에 필요한 모든 결정을 마쳤다.

## ⑤ 검증 계획

- **PR 1 (서버 · AI 연동 · 자동 저장 시험)**:
  - API 키 없이 도는 자동 시험(가짜 AI 응답 주입):
    - [G1] 거절 시험: 빈 문자열(`""`), 공백 문자열(`"   "`), 1,001자 문자열을 넣었을 때 `400` 상태 코드로 거절하고 AI 호출이 일어나지 않는지 확인(조건마다 변조본 대조).
    - [G2·G3] 성공 및 저장 시험: 정상 한영 혼용 문장을 넣었을 때 3단 구조(`corrected`, `alternatives`, `keyExpressions`)가 반환되고 임시 기록 파일에 최신순으로 쌓이는지 확인.
    - [G4] 시크릿 점검: 응답 본문과 클라이언트 정적 파일 어디에도 환경변수 키 값이 포함되지 않는지 확인.
- **PR 2 (화면 동작 및 전체 연결 확인)**:
  - 실제 화면(UI)에서 ① 영문/한영 혼용 문장 타이핑 입력 → 첨삭 3단 결과 카드 확인, ② 마이크 버튼으로 음성 입력 테스트, ③ 새로고침 후 하단 기록 목록에 방금 첨삭받은 내역이 남아 있는지 화면 캡처 및 실행 결과로 확인한다.
