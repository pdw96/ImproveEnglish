## 문제

- 조각 standalone-mobile-app 은 Gemini API 키를 스마트폰 브라우저 저장소에 **글자 그대로(평문)** 보관한다. 폰을 잠깐 남에게
  빌려주거나 저장소를 들여다보면 키가 그대로 보이고, 남이 그 키로 내 사용량을 쓸 수 있다.
- 키를 지키려고 매번 지우고 다시 붙여 넣기는 번거롭다 — 내 비밀번호로 잠가 두고, 쓸 때만 한 번 풀고 싶다.

## 핵심 사용자와 시나리오

- 사용자: 개인 영어 실력을 키우려는 저자 본인(스마트폰 단독 앱으로 공부하는 1인 학습자)
- 시나리오:
  1. `[앱 설정 · 백업]` 탭에서 Gemini API 키와 비밀번호(4자 이상)를 넣고 **[기기에 API 키 저장 (암호화)]** 를 누른다 — 키는
     암호문으로만 기기에 남고, 지금 열린 창에서는 바로 Gemini 첨삭이 된다.
  2. 앱을 닫았다 다시 열면 금고가 잠겨 있다. 설정 탭 배지가 「잠김」을 보이고, 첨삭은 내장 스마트 코치로 이어진다.
  3. 설정 탭에서 비밀번호만 넣고 저장 버튼을 누르면 금고가 풀리고, 그 창을 닫을 때까지(새로고침 포함) Gemini 첨삭이 된다.

## 성공 기준

- 비밀번호를 넣고 키를 저장하면 기기 저장소(`localStorage`)에 평문 키(`ie_gemini_api_key`)가 남지 않고, 암호문 · 소금(salt) ·
  초기값(IV) 세 값만 남는다.
- 맞는 비밀번호로 해제하면 Gemini 첨삭이 동작한다. 틀린 비밀번호는 「비밀번호(PIN)가 일치하지 않습니다」를 보이고 저장된
  암호문은 그대로 남는다.
- 해제한 뒤 같은 창에서 새로고침해도 해제가 유지되고, 창(앱)을 닫았다 다시 열면 잠긴 상태로 돌아간다.
- 잠긴 동안 설정 탭 배지와 안내 줄이 「연결됨」이 아니라 잠김을 보이고, 첨삭 요청은 내장 스마트 코치 답으로 이어진다.
  (지금은 잠긴 동안에도 「개인 Gemini API 키 연결됨」으로 보인다 — 설계 ⑥ PR 1 이 고친다.)
- 비밀번호를 1 ~ 3자로 넣으면 저장하지 않고 「4자 이상」 안내를 보인다. (지금은 길이를 검사하지 않는다 — 설계 ⑥ PR 1 이
  고친다.)
- 비밀번호 없이 저장하면 조각 standalone-mobile-app 과 같이 평문으로 보관한다(호환). **[키 삭제]** 를 누르면 평문 키 ·
  암호문 · 소금 · 초기값 · 해제 상태 다섯 값이 모두 지워진다.
- 학습 데이터 백업 파일(`.json`)에는 키 · 암호문 · 소금 · 초기값이 들어가지 않는다.

## 하지 않을 일

1. 지문 · 얼굴 인식 같은 생체 인증 잠금은 넣지 않는다.
2. 비밀번호 찾기 · 재설정은 없다 — 비밀번호를 잊으면 **[키 삭제]** 뒤 키를 다시 넣는다.
3. 단어장 · 첨삭 기록 같은 학습 데이터는 암호화하지 않는다 — 금고는 API 키만 지킨다.
4. 첨삭 화면에서 해제 창을 띄우지 않는다 — 해제는 설정 탭에서만 한다.
5. PC 서버 모드의 키 보관(환경변수 `.env`)은 바꾸지 않는다.

## 제약

- 스택 · 비용: 브라우저 내장 암호 기능(Web Crypto API)만 쓴다 — 외부 라이브러리 · 유료 서비스 없음, 비용 0원.
- 리뷰 한도: 2회차를 넘기면 소유자(저자)가 직접 판정한다.
- 감사 회차: 닫기 전 — `audit-secrets`(바뀌는 것이 자격증명의 보관 · 암호화 · 해제 상태의 경계라서. 조각
  standalone-mobile-app 의 `audit-secrets` 회차 9 는 평문 보관만 봤다)
